# Configuration that lives inside the running Mailman containers

Several files were edited by hand inside the running containers rather than in
this repository. They survive a host reboot (Docker restarts the same
container) but are **lost whenever a container is recreated**, for example by
`docker-compose up` after an image rebuild. This directory now holds copies of
those files, captured from the live containers on 2026-10-14, together with
`apply-container-config.sh`, which pushes them back into running containers.

| Repo file | Container | Destination | Purpose |
|-----------|-----------|-------------|---------|
| `httpd.conf` | `mail_apache_1` | `/usr/local/apache2/conf/httpd.conf` | Access control for Postorius/HyperKitty is `require shib-session` (any federated login) instead of the old per-user `Require shib-attr mail` list. Adds `RewriteCond`/`RequestHeader` rules that map two identities (`dhs@mit.edu` to `dhs@ligo.mit.edu`, `894652114@fullerton.edu` to `josmith@fullerton.edu`) so Mailman sees the user's canonical address. `ServerAdmin` is `ahnitz@syr.edu`. |
| `postfix/main.cf` | `mail_postfix_1` | `/etc/postfix/main.cf` | Adds `smtpd_recipient_restrictions = permit_mynetworks, check_recipient_access hash:/etc/postfix/access, reject` so only known list addresses are accepted from the internet. The `myhostname`, `relayhost` and `mynetworks` values are also baked in here; the image's entrypoint normally substitutes them from `mailman-env.sh`. |
| `postfix/access` | `mail_postfix_1` | `/etc/postfix/access` (then `postmap`) | The allowlist of list addresses. **Every new list created through COmanage must be added here and `postmap` run, or mail to it is rejected.** |
| `restart-apache` | `mail_apache_1` | `/etc/cron.daily/restart-apache` | Daily job that installs the renewed Let's Encrypt certificate and reloads Apache. Fixed on 2026-10-14 (missing space in a `cp` path, and `apache2ctl` renamed to `apachectl`); the old version silently failed every day. |

`httpd.conf` is also baked into the image by `Dockerfile` (`COPY httpd.conf`),
so a rebuild with `. build-mailman.sh` reproduces the live Apache config. The
`SSLCertificateChainFile` line is kept commented out in the repo copy because
the container's `start.sh` uncomments it at startup when a chain file is given.

## Re-applying after a container is recreated

```sh
./apply-container-config.sh
```

The script copies each file into its container, rebuilds the Postfix access
map, checks the Apache config, and reloads Apache and Postfix gracefully.

## Snapshots

Local Docker images tagged `*:live-20261014` were created with `docker commit`
from the running `mail_apache_1` and `mail_postfix_1` containers as a last
resort fallback. They are not pushed anywhere.
